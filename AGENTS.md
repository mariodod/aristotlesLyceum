# AGENTS.md

Operating manual for anyone (human or agent) changing this repository.

Read this before you touch a file. It encodes decisions that are expensive to
re-derive and a set of rules that keep the project coherent.

---

## 1. What this project is

**Aristotle's Lyceum** is a 2D pixel-art narrative game in the tradition of
_Undertale_. Isaac hates philosophy class, has an exam the next morning, falls
asleep studying Aristotle, and dreams his way through ancient Greece, the
history of science, and back to the exam.

It is a **story first** game. The interesting artefact is the writing; the
systems exist to serve it.

### Non-negotiables

| Rule                                           | Why                                                                                                                                                                                 |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The project is written in **English**          | The brief arrived in Spanish, but every document, string, commit and comment in this repository is English. Spanish is a future locale, not a second language of the source.        |
| **No Undertale assets.**                       | We borrow a genre and a tone, never a sprite, a font, a sound or a line of text. Everything in `public/` is generated from code in `tools/`.                                        |
| Every philosophical claim carries a **source** | The Codex is the educational spine of the game. `src/data/codex/` entries must name the Aristotelian work they come from, and `npm run content:check` enforces it.                  |
| **Content is data, not code**                  | A chapter is a typed object in `src/data/script/`. If you need a new kind of story beat, add a step kind to the runtime and the type — do not branch on chapter ids inside a scene. |

## 2. Stack

| Layer         | Choice                        | Notes                                                                           |
| ------------- | ----------------------------- | ------------------------------------------------------------------------------- |
| Language      | TypeScript 6, `strict`        | `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`  |
| Engine        | Phaser 4.2                    | Scenes, input, tweens, bitmap text, audio                                       |
| Bundler       | Vite 8                        | `base` is `/aristotlesLyceum/` in production, overridable with `VITE_BASE_PATH` |
| Unit tests    | Vitest 5                      | Node environment, `tests/unit/**` only                                          |
| Browser tests | Playwright                    | `tests/e2e/**`, Chromium by default                                             |
| Lint / format | ESLint 10 (flat) + Prettier 3 | 100 columns, single quotes                                                      |
| Art           | Generated by Node scripts     | `tools/assets/` — no binary assets are hand-drawn                               |
| Audio         | Generated by Node scripts     | `tools/audio/` — planned for M8                                                 |
| Font          | Generated bitmap font         | `tools/assets/font.mjs`, 5x7 body on a 7px advance                              |
| CI/CD         | GitHub Actions → GitHub Pages | `.github/workflows/`                                                            |

### Why this stack

This repository is the sibling of `minesNgoblins`, which already ships a
Phaser + TypeScript browser game with a procedural pixel-art pipeline, a
Playwright suite and a Pages deployment. Reusing that shape means:

- every tool in the chain is already proven on this machine;
- the asset pipeline is **code-generated**, which is the only way art gets made
  here at all — nobody is going to hand-paint sprites;
- the deployment path is a copy of a working configuration.

Godot was considered (the author also maintains `fiel-al-libro` in Godot 4) and
rejected for this game: hand-authoring `.tscn` files is error-prone, GDScript
is harder to verify from a terminal, and the target is a web build.

## 3. Commands

```bash
npm install
npm run dev            # dev server on http://127.0.0.1:5173
npm run build          # typecheck + production build into dist/
npm run preview        # serve dist/ on http://127.0.0.1:4173

npm run typecheck      # tsc --noEmit
npm run lint           # eslint .
npm run format         # prettier --write .
npm run format:check   # prettier --check .

npm run test           # vitest run (unit)
npm run test:e2e       # playwright test (browser)

npm run assets         # regenerate public/assets and src/data/asset-manifest.json
npm run content:check  # validate every script, codex entry and reference
```

`npm run assets` and `npm run content:check` are not optional extras. The
generated art pack and the manifest are **committed**, so a change to a
generator must be followed by a regeneration, and a new chapter must be
followed by a content check.


### Layering rules

```
data  →  systems  →  services  →  entities  →  scenes
```

- **`data/`** is pure data. No Phaser import, no side effects.
- **`systems/`** is pure logic. No Phaser import. If it can be unit tested in a
  Node environment, it belongs here.
- **`services/`** owns state that outlives a scene. Only the save service
  exists today.
- **`entities/`** are Phaser objects with a visual job.
- **`scenes/`** compose entities and translate runtime events into
  presentation. A scene never contains story rules.

**Never** import from `scenes/` or `entities/` into `systems/` or `data/`.
**Never** put story content in a scene.

## 5. Writing a chapter

A chapter is a `StoryScript` in `src/data/script/`. The runtime is a small
interpreter over labelled steps.

```ts
export const ACT_ONE: StoryScript = {
  id: 'act-one',
  chapter: 'act-one',
  title: 'Act I — The Desk',
  backdrop: 'backdrop-bedroom',
  steps: [
    { at: 'open', kind: 'chapter', title: 'ACT I', subtitle: 'The Desk' },
    { at: 'stage', kind: 'stage', actors: [{ character: 'isaac', x: 190 }] },
    { at: 'line', kind: 'say', speaker: 'isaac', text: 'Nine hours.' },
    {
      at: 'ask',
      kind: 'choice',
      speaker: 'aristotle',
      prompt: 'What do you do?',
      options: [
        { label: 'Read on.', goto: 'read-on', stat: { stat: 'reason', delta: 1 } },
        { label: 'Shut it.', goto: 'shut-it', stat: { stat: 'empathy', delta: 1 } },
      ],
    },
    { at: 'read-on', kind: 'say', speaker: 'isaac', text: 'He reads on.' },
    { at: 'shut-it', kind: 'say', speaker: 'isaac', text: 'He shuts it.' },
    { at: 'end', kind: 'end' },
  ],
};
```

### Step kinds

| Kind         | Purpose                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------- |
| `chapter`    | Shows the act card.                                                                               |
| `stage`      | Places characters on the stage and optionally swaps the backdrop.                                 |
| `say`        | One line of dialogue, with an optional expression.                                                |
| `choice`     | A menu. Options jump to a label and may move a stat or set a flag.                                |
| `codex`      | Unlocks a Codex entry. The id must exist.                                                         |
| `stat`       | Moves a stat directly.                                                                            |
| `flag`       | Sets a boolean flag.                                                                              |
| `jump`       | Unconditional jump to a label.                                                                    |
| `branch`     | Jumps to one of two labels depending on a flag. This is how a chapter reaches a different ending. |
| `chapterEnd` | Names the ending the player reached. The scene shows it on the chapter-complete card.             |
| `end`        | Ends the chapter. The last step must be an `end`.                                                 |

### Rules for scripts

1. **Every label is unique** inside a chapter, and every `goto`/`jump`/`branch`
   target must exist. `npm run content:check` enforces both.
2. **Branches merge explicitly.** A choice branch must jump back to a common
   step, otherwise the steps after it run twice. The reachability check in
   `systems/dialogue/reachability.ts` proves that no step is orphaned.
3. **A choice's only continuations are its options.** The step after a choice
   is not reachable unless an option jumps to it. That is deliberate: it is
   what forces branches to merge.
4. **Speakers come from `CHARACTER_IDS`** in `src/types/story.ts`. Adding a
   character means adding the id there and the definition in
   `src/data/characters.ts`.
5. **Codex entries live in a file named after the chapter that unlocks
   them** (`src/data/codex/act-two.ts`). Every entry must be unlocked by that
   chapter or the linter reports it as an orphan.
6. **Lines are short enough to read.** The linter rejects a line over 420
   characters. Aim for two or three sentences.
7. **A chapter ends with `end`.**
8. **A chapter owns the flags it sets.** Flags written by a `flag` step or a
   choice's `setFlag` are cleared when that chapter starts, so replaying a
   chapter cannot inherit the previous run's choices. Flags a chapter only
   _reads_ are not owned by it, so an act can branch on what an earlier act
   decided. `systems/dialogue/script-flags.ts` computes the owned set.

## 6. The art pipeline

There is no image editor in this workflow. Art is code.

- `tools/assets/pixel.mjs` — a tiny deterministic pixel canvas with no
  dependencies. `drawMap` paints an authored string map through a palette.
- `tools/assets/png.mjs` — a hand-rolled PNG encoder (zlib only).
- `tools/assets/palette.mjs` — the shared colours.
- `tools/assets/characters.mjs` — characters as authored pixel maps.
- `tools/assets/backgrounds.mjs` — backdrops painted with shapes and ordered
  dithering.
- `tools/assets/font.mjs` — the bitmap font and its BMFont XML.
- `tools/assets/build-assets.mjs` — the only entry point. It writes
  `public/assets/**` and `src/data/asset-manifest.json`.

### Rules for art

1. **Characters are authored maps.** A character is an array of equal-length
   strings, one character per pixel, with `.` for transparent. `validateMap`
   fails the build on a row of the wrong length, so a miscount is loud.
2. **One outline colour for the whole cast** (`0x14121a`). Characters must
   read as one drawing system.
3. **Backdrops keep their content above `y = 232`.** The dialogue box covers
   the bottom of the screen. Furniture that hides behind the text box is
   furniture nobody sees.
4. **The palette is shared.** Do not introduce a colour that is not in
   `tools/assets/palette.mjs`.
5. **Regenerate after every generator change** and commit the result.

## 7. Testing

| Layer   | Tool                            | Covers                                                                        |
| ------- | ------------------------------- | ----------------------------------------------------------------------------- |
| Unit    | Vitest                          | `systems/`, `data/`, `services/` — anything with no Phaser import             |
| Browser | Playwright                      | Scene flow, input, the dialogue box, the choice menu, the endings, save state |
| Content | `npm run content:check`         | Script integrity, codex references, source presence, unreachable steps        |
| Visual  | `node tools/qa/screenshots.mjs` | Capture the title and Act I for review                                        |

### Rules

- A pure rule lives in `systems/` and gets a unit test. If it is hard to unit
  test, it is in the wrong layer.
- A scene flow gets a Playwright test that ends with
  `expect(errors).toEqual([])`.
- Browser tests read `window.__LYCEUM_TEST__`, published by
  `src/utils/test-hooks.ts`. The publisher is DEV-only; a production bundle
  must not expose the hook.
- Use `nextLine()` and `advanceUntilChoice()` from `tests/e2e/helpers.ts`
  instead of raw key presses, so tests do not depend on typewriter speed.

## 8. Code style

- `kebab-case.ts` files, `PascalCase` classes and types, `camelCase` values,
  `SCREAMING_SNAKE` for module constants.
- Named imports only; `import Phaser from 'phaser'` is the sole default.
- `import type` for type-only imports (enforced by ESLint).
- Relative imports carry the `.ts` extension. This is deliberate: it lets
  Node run the game's own modules directly, which is how
  `tools/content/check-content.mjs` reads the story data.
- No `console.log` in `src/`. Generators under `tools/` may log.
- Comments explain **why**, not what. Every tuning constant carries the
  reason it has the value it has.
- Phaser `Rectangle` and `Ellipse` are centre-origin. Use `setOrigin(0, 0)`
  whenever the object is laid out against a top-left corner. This has already
  cost one debugging session; do not repeat it.
- A game object created with `scene.add.*` belongs to the scene's display
  list, not to a container. To draw something inside the dialogue box, add it
  to the container as well, or it renders at depth zero behind the panel.
  `TextBox.optionsRendered` exists to guard exactly this.

## 9. Definition of done

A change is done when:

- `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run test`
  and `npm run content:check` all pass;
- `npm run build` succeeds;
- new behaviour is covered by a unit test or a browser test;
- new art is regenerated and committed with its generator;
- new content has sources;
- the documentation under `docs/` is updated if a decision changed.
